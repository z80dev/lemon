# Native macOS app

`LemonBotMacApp` hosts the shared `LemonBotRootView(store:)` and one menu-bar entry. Requires macOS 14+, the shared LemonBotKit/LemonBotUI products, and the authenticated product backend. The Apple project owns build/signing settings; this directory supplies `Info.plist` and `LemonBotMac.entitlements`.

## Connect iPhone

Open **Connect iPhone** from the signed-in workspace. The guide first explains Tailscale installation/login on both devices, same-tailnet membership, ACL access to the HTTPS listener, MagicDNS, trusted TLS and the already running **Bot** backend (not Lemon Web or the operator WebSocket). The Mac app never installs or starts services, provisions Tailscale or replaces a configured remote backend with a local workspace.

Choose **Check connection readiness**. The Mac reads authenticated `/v1/identity` at the account's configured backend, resolves its advertised `publicUrl`, and verifies credential-free `/v1/setup` followed by authenticated `/v1/identity` at that exact HTTPS `.ts.net` origin. Instance and workspace must match the trusted baseline; the first successful check pins the instance in the existing Keychain account. Loopback, redirects, HTML/Phoenix/wrong-service responses, incomplete descriptors and changed identity fail closed. Probes have a ten-second overall deadline per preflight and a 16 KiB descriptor limit, with normal system TLS, no cookies or cache. This proves reachability **from the Mac**, not physical iPhone connectivity.

The guide displays the **exact verified advertised origin**, instance and workspace before enabling **Create QR code**. The backend must already advertise that origin in `LEMON_BOT_PUBLIC_URL`; the UI cannot override the issued QR origin. If an operator explicitly chooses Tailscale Serve outside the app, inspect its existing routes first, select an unused HTTPS port/listener, preserve every existing route and port, and route only to the actual running Bot backend. Never reset Serve, overwrite another service or enable Funnel. This flow constructs or executes no Serve/service commands and changes no sandbox or entitlements.

The one-use QR is rendered locally with CoreImage. On iPhone scan it or securely paste the copied link, review the workspace/origin/expiry, then request connection. Compare the exact device name and six-digit code, select **The exact device name and code match my iPhone**, then explicitly **Approve this iPhone**; deny unfamiliar requests. Approval is not completion. The foreground window checks authoritative request status every two seconds while a request is active, stopping at its original expiry or terminal state; existing product realtime also updates it. **Connected — iPhone completed pairing** is shown only for the backend's consumed receipt. Refresh/check-readiness remain available after a network failure; no approval is replayed.

Polling retains each observed request ID and reads `/v1/pairings/:id` through completion or the original expiry. The pending-request list intentionally excludes approved/consumed rows; absence from that list never removes an observed or completed request.

Issuance, reconciliation and approval/denial recheck identity before mutating. An unknown issuance uses only its original nonce; unknown approval/denial is reconciled by GET without repeating approval. Expired QR/link output is hidden locally even before another server update. Closing the window or backgrounding the app stops polling. The phone receives its own Keychain-backed revocable session, not the desktop password or operator credential. Revoke it through account Devices / sessions. Treat the QR, copied one-use link and screenshots as temporary secrets.

## Explicit companion and capture

Open **Lemon Bot → Settings** to choose a Bot and optionally enable one compact companion. Global quick-composer and hold-to-talk shortcuts are disabled by default. Click a shortcut recorder, then press a key with Command, Control or Option. Escape cancels; Delete clears the shortcut. Choose **Save device-local settings** to apply. Global shortcuts pause while recording and registration conflicts are reported when saving. The recorder receives keys only while explicitly focused; there is no global keyboard monitor or Accessibility permission.

An unset recorder shows **Record Shortcut**, changes to **Type shortcut…** during capture, and displays native modifier symbols afterward (for example, **⌃⌥Space**). This display does not change the stored shortcut.

The **Conversation** menu lists **Previous Bot** (⌘[) and **Next Bot** (⌘]); these are the sole navigation bindings.

Summon opens the selected Bot’s same shared mini-composer, labelled with account/workspace/machine. **Services → Send selection to Lemon Bot** imports only the selection provided by the invoking application; **Choose files** uses the native user-selected file picker. Content stays in that conversation’s draft until explicit Send. No screen reading, desktop streaming, clipboard polling/history, ambient listening or wake-word capture exists.

Device/account settings persist through `LemonBotStore.saveLocalSettings(_:)` as the exact `ClientLocalSettings` fields; this is device-local, not an invented settings HTTP endpoint.

## Desktop pet

An optional original pixel lemon floats above your windows and reacts to live Bot activity, approvals and connection state. It is off by default, passes clicks through transparent pixels, and uses Mac-wide preferences independent of accounts. See the [desktop pet guide](DesktopPet.md) for controls, Codex package imports, privacy and DEBUG previews.

## Voice

The macOS settings window lists actual Core Audio microphone inputs. Choose a device or **System default** and refresh after plugging in hardware; a disconnected selected device reports an error rather than silently selecting another microphone. This hardware choice is local to this Mac, changes only the explicit capture audio unit, and does not grant microphone access to a remote Bot.

Holding the configured PTT combination requests microphone/Speech authorization on first use, shows a microphone-on owner/target panel, records only while held, and plays optional mic-on/off cues. Release turns the microphone off and transcribes for editable review. Escape/Discard clears the temporary recording and text. Apple Speech requires on-device recognition; if unavailable/denied, the reviewed recording can be **explicitly** uploaded for backend transcription. Backend prerequisites/errors are shown verbatim through the shared API errors. Capture is bounded to ten minutes and stops when the voice panel closes, the account changes or the app quits.

**Keep as unsent draft** appends reviewed text to the original conversation, preserving existing attachments/reply. It never sends. An explicit active voice chat is a backend VoiceSession: Record → Stop/review → **Send reviewed utterance** uses ordinary message sending with `voiceSessionId`, and authoritative assistant replies use real backend speech segments. `AVSpeechSynthesizer` is a clearly labelled on-device fallback when backend speech fails; the actual backend prerequisite remains visible. Call mute/settings/end are explicit current-revision/nonced requests. Calls remain accessible from the menu when navigating elsewhere. Unknown sends are fenced from another send; inspect backend entries/runs rather than automatically replaying. Voice preview calls the fixed backend Bot sample endpoint without creating work. Persisted voice memos remain shared transcript cards and play their authorized actual audio, not synthetic placeholder files.

## Notifications and launch

Launch restores a saved Keychain-backed account, registers this Mac, and publishes viewed-room foreground presence with a 20-second refresh. Explicit notification enablement asks macOS permission. Local Debug builds use local notifications only; provisioned Release builds also register APNs. Existing notification snapshots establish a baseline, rather than alerting on historical inbox contents. Hidden Bots, account preferences and the exact active viewed room suppress local delivery; approvals retain individual IDs and informational results coalesce by room. Notification taps and `lemonbot://` URLs use the shared authorized token-free resource router and never resolve gates.

Mac Debug selects `LemonBotMacDebug.entitlements`, preserving sandbox, outbound network, explicit microphone/Speech and user-selected read-only files without profile-requiring APNs or App Group capabilities. Its empty `APS_ENVIRONMENT` disables remote registration at startup and in both notification permission actions; local notification permission and delivery remain available. Mac Release retains `LemonBotMac.entitlements` and production `APS_ENVIRONMENT`, requiring a matching APNs signing profile/team and the backend's real key/team/topic configuration. The Mac has no App Group consumer; the iOS app/share group's entitlement and APNs configuration are unchanged. No screen/Accessibility/full-disk entitlement is requested.

## Integration checks (parent-owned)

Generate the XcodeGen project and build the LemonBotMac scheme with `CODE_SIGNING_ALLOWED=NO` for compilation-only CI. For actual login/Keychain checks, use the ad-hoc-signed Debug build and exact replacement/launch commands in the [Apple build guide](../README.md#generate-build-and-launch). Sign in, quit and relaunch that same app, and confirm the saved account restores; also save/resume/cancel a pending pairing across a restart. macOS uses encrypted, non-iCloud-sync local login-Keychain items, not iOS `ThisDeviceOnly` protection. Do not infer storage success from mocked lifecycle tests. On a signed Mac, also exercise shortcut conflicts/press-release during permission dialogs, denied/no-input Speech, draft preservation across conversations/accounts, actual backend voice preview/transcription/TTS and fallback, active-call mute/end, explicit Services/file import, foreground same-room suppression versus another room, and revoked/foreign-workspace deep links. Implementation workers do not run builds, tests, lint, formatting, XcodeGen, permission prompts or provider probes.
