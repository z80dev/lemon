# Keyed export scheduler

Repair `runJobs<T>(jobs: Job<T>[], options: {concurrency: number; signal?: AbortSignal}): Promise<JobResult<T>[]>` in src/pool.ts and integrate src/exports.ts. The existing src/types.ts describes the public shapes: Job is `{key: string, run(signal: AbortSignal): T | PromiseLike<T>}`, result is fulfilled/value, rejected/reason, or aborted/reason. Results are in INPUT order, exactly one per job, including duplicate keys. Jobs with the same key must never overlap. Start as many eligible jobs as capacity allows; each scheduling pass chooses the earliest not-yet-started input whose key is not active (a blocked earlier job must not block other keys). On settlement release its key/slot and immediately schedule newly eligible jobs. Start a job at most once. Synchronous throws and rejected promises yield rejected results with the original reason; they do not stop unrelated jobs. Await every started job, even when one fails.

Concurrency must be a positive integer; otherwise return a rejected Promise with RangeError before invoking any job (even for empty input). Empty valid input resolves []. When a caller signal exists, pass that IDENTICAL signal to each started job; otherwise pass a non-aborted AbortSignal. On abort, never start remaining jobs; mark all not-started results `{status:"aborted",reason:signal.reason}`. Already-started jobs receive the signal but keep their actual fulfilled/rejected outcome, even if they ignore cancellation. The returned promise waits for them, not merely for the abort. A pre-aborted signal starts nothing. Clean up your abort listener when done. Preserve input jobs without mutation. The run function returns ordinary values or thenables as well as native promises.

`exportRecords(records, write, options)` in src/exports.ts must submit one job per record (key=record.account, invoking `write(record, signal)`) through the scheduler. `write` returns a string or promise-like string. Return `{receipts: string[], failed: string[], skipped: string[]}`: receipts contains successful values, failed contains IDs of rejected records, skipped contains IDs of unstarted-aborted records, each subsequence in input order. Handle repeated account and record IDs without deduplication. Keep typed public APIs and all existing entry points. Add tests using deferred promises rather than elapsed-time assertions. Run `node --test test/*.test.ts`.
